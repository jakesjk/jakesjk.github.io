원칙 05 · 판단 · 해결 사례 A · Lunarc

출시 2~4개월 지연까지 비용으로 적고 백엔드를 서버리스로 옮기기로 정해 5일 만에 백엔드를 운영에 올렸습니다(월 운영비 $0)

문제

  1. Spring Boot + PostgreSQL 백엔드를 운영에 올리기 직전이었고 운영 데이터는 아직 없었습니다.
  2. 하루 사용자 1만 명 규모가 되면 Cloudflare가 BaaS(Supabase)보다 월 $30~50 싸다는 계산이 있었지만 옮기면 출시가 2~4개월 늦어질 수 있다고 봤습니다.
  3. 그대로 출시할지 옮길지 정해야 했습니다.

해결 과정

  1. 출시 지연 2~4개월을 비용으로 적고 사용자가 늘었을 때의 비용 · 엣지 실행 학습 · 표준 정합을 함께 따져 2026-05-10에 Workers + D1로 옮기기로 했습니다.
  2. 운영 데이터가 없어 동기화 없이 새로 세우는 방식을 골랐고 옮기기 전에 호출처가 없는 모듈을 찾아 옮기지 않고 지웠습니다.
  3. 남은 7개 모듈을 한 번에 옮기지 않고 모듈마다 설계 검토 → 구현 → 코드 리뷰 → 테스트를 통과해야 다음으로 넘어갔습니다.

결과

  • 5일결정에서 백엔드 운영 배포까지 · 05-10 → 05-15
  • $0월 운영비
  • 7단계 이관한 모듈
  • 227파일걷어낸 Spring Boot 코드

조건운영 배포 전에 옮겨 데이터 이전은 없었습니다 · 앱 첫 출시 2026-07-14 · 누적 다운로드 44(2026-10 기준) · Cloudflare 무료 사용량 안(Workers 하루 요청 10만 건)
