원칙 05 · 판단 · 해결 사례 B · Lunarc

실사용자 10명의 기록으로 완주 0인 기능을 판단해 iOS 코드 6,579줄을 걷어내고 화면을 일정 중심으로 바꿨습니다

문제

  1. 챌린지와 집중 세션 기능이 핵심인 하루 일정 화면과 자리를 다투고 있었습니다.
  2. "쓸 것 같은데 안 쓰는 것 같다" 수준의 감으로는 판단이 서지 않았습니다.
  3. 남길지 뺄지 근거가 필요했습니다.

해결 과정

  1. 운영 DB에서 계정 41개 중 테스트 시드 31개를 걸러 실사용자 10명의 기록만 봤습니다.
  2. 일정은 146건인데 챌린지는 참여 8행에 완주 0건, 집중 세션은 2건이라 두 기능을 함께 빼고 탭을 일정 중심으로 바꿨습니다.
  3. 복원 절차를 문서로 만들어 실제로 되살려 빌드까지 확인한 뒤 iOS 코드 35파일 6,579줄을 걷어냈습니다.
  4. 실사용 1건이었던 익명 한 줄 공유는 혼자 써도 가치가 있는 구조라 남겼습니다.

결과

  • 10명시드 31개를 걸러 낸 실사용자
  • 0챌린지 완주
  • 6,579줄걷어낸 iOS 코드 · 35파일
  • 복원 확인절차대로 되살려 빌드 성공
