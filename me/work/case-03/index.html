원칙 06 · 운영 · 해결 사례 A · Lunarc

로그인 만료를 오프라인으로 읽어 일정 4건이 중복되던 사고를 저장 구조를 바꿔 다시 생기지 않게 했습니다

문제

  1. 운영 환경에서 일정이 중복 생성되는 사고가 났습니다(레코드 4건).
  2. 로그인 세션 만료를 앱이 오프라인 상태로 잘못 분류하고 있었습니다.
  3. 그동안 만든 일정이 오프라인 큐에 쌓였다가 재로그인 때 한꺼번에 다시 전송됐습니다.

해결 과정

  1. 큐 로직만 고치지 않고 재전송 대기열을 저장소로 쓰던 구조 자체를 원인으로 봤습니다.
  2. 비로그인 상태에서는 기기 저장소를 정본으로 삼아 서버와 통신하지 않고 로그인 순간에만 한 번 병합하게 바꿨습니다.
  3. 인증 오류와 오프라인을 분리하고 생성 요청에 멱등 키와 DB 유니크 제약을 걸어 중복을 구조적으로 막았습니다.

결과

  • 4건사고로 중복된 레코드
  • 0회비로그인 구간 서버 통신
  • 1회로그인 순간 병합
  • 2겹멱등 키 + 유니크 제약
