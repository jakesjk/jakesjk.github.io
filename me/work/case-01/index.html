원칙 05 · 판단 · 해결 사례 A · Lunarc

매달 고정비가 나가던 서버를 요청 시 실행 구조로 옮겨 운영비를 월 $0으로 만들었습니다(중단 0 · 유실 0)

문제

  1. Spring Boot + PostgreSQL 서버는 상시 인스턴스가 필요해 사용자가 없어도 매달 고정비가 들었습니다.
  2. 무료 티어로 낮추면 콜드스타트로 첫 응답이 늦어졌습니다.
  3. 출시를 앞둔 시점이라 그대로 출시할지 옮길지 정해야 했습니다.

해결 과정

  1. 현행 유지 · BaaS 전환 · Cloudflare Workers + D1 세 안을 비용 · 리스크 · 출시 지연으로 비교했습니다.
  2. BaaS는 인증과 영수증 검증이 벤더에 묶여 뺐고 Workers + D1은 출시가 2~4개월 늦어지는 것을 비용으로 적은 뒤 골랐습니다.
  3. 14개 모듈을 한 번에 옮기지 않고 모듈마다 설계 검토 → 구현 → 성능 검토 → 코드 리뷰 → 테스트 → 수동 검증을 통과해야 다음으로 넘어갔습니다.

결과

  • $0월 운영비
  • 0이관 중 서비스 중단
  • 0데이터 유실
  • 14단계 이관한 모듈

조건누적 다운로드 44 규모 · Cloudflare 무료 사용량 안(Workers 하루 요청 10만 건). 사용자가 늘면 요금이 붙는 지점은 따로 계산해 두었습니다.
