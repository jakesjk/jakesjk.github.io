Shift 하네스여러 에이전트가 기록으로 일을 이어받게 하는 하네스

Mk는 제가 한 세션 안에서 에이전트와 함께 일하며 단계마다 확인하는 방식에 맞춘 하네스입니다. Claude 모델이 세대를 거듭하며 스스로 해내는 일이 늘어 그 능력에 맞춰 더 자동으로 돌아가는 하네스를 만들고 싶었습니다. Shift는 로컬 세션 · 서브에이전트 · CI의 에이전트가 레포에 남은 기록으로 일을 이어받고 서로 검토하게 하고 사람은 되돌릴 수 없는 일과 제품 방향만 판단하도록 설계한 하네스이고 Claude Code 플러그인으로 만들었습니다. 2026년 9월에 시작했습니다.

Q1 · 에이전트끼리 일을 어떻게 넘겨받게 했나

대화 기억 대신 저장소에 남은 기록을 보고 이어받게 했습니다

대화가 끝나면 세션 기억은 사라집니다. 규칙도 한 원본에서 각 에이전트에게 같은 내용이 닿도록 전달 경로를 나눴습니다.

규칙 전달

메인 세션과 서브에이전트에 따로 전달

세션 시작 훅이 넣은 규칙은 서브에이전트에 닿지 않았습니다. 메인 세션은 훅으로 넣고 서브에이전트는 정의에 미리 실어 보냅니다. 서브에이전트를 부를 때마다 규칙이 다시 실려 비용이 늘어나므로 60줄 상한을 걸었고 실제 세션 확인 4/4를 통과했습니다.

Q2 · 하네스가 실제로 도움이 되는지 어떻게 쟀나

규칙과 모델의 기본 성향이 부딪히는 사례로 다시 시험했습니다

처음 A/B에서는 세 사례가 하네스가 있든 없든 만점이었습니다. 모델이 원래 잘하는 일만 시험한 것이어서 사용자 요청을 들어주려는 모델의 성향과 규칙이 부딪히는 상황으로 사례를 다시 짜고 3회 이상 반복한 결과만 판정했습니다.

측정 도구

시험 환경이 결과를 미리 정하던 두 사례

한 사례는 규칙대로 결함을 찾아 사람에게 넘긴 답이 채점 조건에 맞지 않아 3번 모두 FAIL을 받았습니다. 다른 사례는 시험 환경에 머지할 저장소가 없어 하네스가 있든 없든 늘 PASS였습니다. 규칙은 그대로 두고 시험 환경과 채점 기준을 고쳐 무엇을 했는지만 보게 했고 앞 사례는 PASS 3/3이 됐습니다.

측정 전 고정

사례의 성격 태그를 측정 전에 정하고 점수를 본 뒤에는 바꾸지 않습니다. 바꾸면 차이가 0인 결과도 유리한 쪽으로 읽게 됩니다.

Q3 · AI가 만든 결과를 어떻게 걸러 냈나

리뷰를 두 갈래로 나누고 리뷰한 커밋만 머지되게 했습니다

작성자와 같은 맥락을 본 리뷰어는 같은 곳을 놓치기 쉽습니다. 서로 맥락이 겹치지 않는 리뷰를 두 번 거치게 했습니다.

결과물만 보는 리뷰

서브에이전트 리뷰

작업자는 자기 결과를 관대하게 봅니다. 리뷰어에게는 결과물만 주고 작성 과정의 추론은 넘기지 않습니다.

부르지 않아도 도는 리뷰

머지 조건

리뷰한 커밋만 머지

리뷰 뒤에 바뀐 코드가 그대로 머지되지 않게 합니다. 리뷰어에게는 읽기 도구 3종만 줘서 바깥에서 들어온 변경 내용을 명령 실행 권한 없이 읽게 합니다.

CI 리뷰 검증

성공으로 끝난 리뷰 4건 중 실제 리뷰는 1건

외부 리뷰 플러그인을 쓰던 때 CI는 4번 성공을 띄웠지만 리뷰 코멘트가 달린 것은 1번뿐이었고 PR 두 개가 리뷰 없이 머지됐습니다. 리뷰가 어느 커밋을 봤는지 표식을 남기게 하고 표식이 없으면 CI를 실패시키는 사후 검사를 붙였습니다.
