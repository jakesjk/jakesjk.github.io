일하는 방식

AI 협업 원칙과 해결 사례

AI로 빠르게 만들수록 사람이 정해야 할 것이 늘어납니다. 원칙마다 그 원칙으로 실제 문제를 푼 사례를 붙였습니다.

  1. 01

    AI가 만든 코드는 검증을 통과해야 믿습니다

    AI가 쓴 코드는 테스트를 통과한 뒤에도 결함을 일부러 심어 테스트가 실제로 잡아내는지 확인하고 합쳤습니다.

    해결 사례

    사례 A자동 검증을 모두 통과한 PR 11건을 다른 모델로 다시 읽어 놓친 결함 2건을 찾아 고쳤습니다→사례 B실제 결제 영수증이 100% 거부되던 검증 결함을 찾아 고치고 같은 실수를 잡는 테스트를 붙였습니다→
  2. 02

    AI 기능은 모델 바깥부터 설계합니다

    LLM 기능은 호출 비용 상한, 출력 검증, 실패 경로를 먼저 정한 뒤 모델을 붙였고 실패하면 어느 단계에서 틀렸는지 로그로 찾을 수 있게 했습니다.

    해결 사례

    사례 A같은 거절에 추론을 두 번씩 쓰던 재시도를 없애 거절 경로 추론 비용을 절반으로 줄였습니다→사례 B원가를 모르던 무제한 요금제를 편당 원가 $0.29로 계산해 월 20편 상한으로 바꿨습니다→
  3. 03

    직접 돌려 본 결과로 정합니다

    모델 선택이나 서버 한계처럼 직관으로 정하기 쉬운 것도 실제로 돌려 본 결과를 표로 비교해 정했습니다.

    해결 사례

    사례 A번역 후보 2개를 204건으로 비교해 뜻을 뒤집던 전용 모델을 걸러 내고 새 비용 없이 모델을 정했습니다→사례 B부하 테스트로 저하가 시작되는 구간(500~750 RPS)을 찾아 운영 한계를 숫자로 확보했습니다→
  4. 04

    꼭 지킬 규칙은 도구로 강제합니다

    반드시 지켜야 할 규칙은 훅으로 강제했고 효과가 없는 규칙은 사용 기록을 대조해 걷어냈습니다.

    해결 사례

    사례 A지켜지지 않던 문서 규칙을 훅 19종으로 바꾸고 효과 없던 2종은 45일 기록으로 걷어냈습니다→
  5. 05

    결정은 되돌릴 수 있게 내립니다

    기능을 뺄 때는 복원 절차부터 만들어 판단이 틀려도 되돌릴 수 있게 한 뒤 코드를 걷어냈습니다.

    해결 사례

    사례 A매달 고정비가 나가던 서버를 요청 시 실행 구조로 옮겨 운영비를 월 $0으로 만들었습니다(중단 0 · 유실 0)→사례 B실사용자 10명의 기록으로 완주 0인 기능을 판단해 iOS 코드 6,579줄을 걷어내고 화면을 일정 중심으로 바꿨습니다→
  6. 06

    만든 것은 출시하고 끝까지 운영합니다

    App Store 심사 반려는 원인을 찾아 고쳐 통과했고 출시 뒤에는 설치 지표로 현지화 결정이 맞았는지 확인했습니다.

    해결 사례

    사례 A로그인 만료를 오프라인으로 읽어 일정 4건이 중복되던 사고를 저장 구조를 바꿔 다시 생기지 않게 했습니다→사례 B현지화 뒤 해외 설치 비중이 32%에서 76%로 바뀐 것을 판매 리포트로 확인했습니다→
